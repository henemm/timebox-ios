# RW_2.3 — Limitation Guard

## Approval

- [x] Approved — implementiert 2026-03-27

## Purpose

Zeigt dem User eine nicht-modale Inline-Warnung wenn die geplante Next-Up-Liste seinen historischen Tagesdurchschnitt (Tasks oder Minuten) ueberschreitet. Das Feature soll realistisches Planen foerdern, ohne den User zu bevormunden — informierend, nicht blockierend.

- **File:** `Sources/Services/LimitationGuardService.swift`
- **Identifier:** `enum LimitationGuardService`

Zusaetzlich betroffen:
- `Sources/Views/NextUpSection.swift` — Inline-Banner unter dem Header
- `Sources/Views/MorningCoachingSection.swift` — Inline-Banner unter dem Header
- `Sources/Views/DayView.swift` — Warning-State berechnen und als Parameter weitergeben

## Implementation Details

### Datenmodell

```swift
/// Ergebnis der Limitation-Pruefung — nil bedeutet kein Problem.
struct LimitationWarning: Equatable {
    /// Anzahl Tasks die sich der User vorgenommen hat.
    let plannedTasks: Int
    /// Summe der effectiveDuration aller Next-Up-Tasks (Minuten).
    let plannedMinutes: Int
    /// Historischer Durchschnitt Tasks/Tag (gerundet auf 1 Nachkommastelle).
    let avgTasks: Double
    /// Historischer Durchschnitt Minuten/Tag (gerundet auf ganze Minuten).
    let avgMinutes: Double
}
```

### Service

```swift
enum LimitationGuardService {

    // Mindestanzahl aktiver Tage im BehavioralProfile bevor gewarnt wird.
    // BehavioralProfileService.minActiveDaysForCapacity = 5, aber wir wollen
    // 14 Tage Wartezeit laut Story (entspricht ~14 aktiven Tagen im 28-Tage-Fenster).
    static let minActiveDaysBeforeWarning: Int = 14

    /// Prueft ob die uebergebene Task-Liste den historischen Schnitt ueberschreitet.
    /// - Parameters:
    ///   - tasks: Aktuelle Next-Up-Tasks des Users.
    ///   - profile: Berechnetes BehavioralProfile (aus BehavioralProfileService).
    /// - Returns: `LimitationWarning` wenn Ueberschreitung vorliegt, sonst nil.
    static func evaluate(
        tasks: [PlanItem],
        profile: BehavioralProfile
    ) -> LimitationWarning?
}
```

**Interne Logik von `evaluate`:**

1. Guard: `profile.avgTasksPerDay != nil || profile.avgMinutesPerDay != nil` — wenn beide nil, return nil (zu wenig Daten).
2. Guard Daten-Qualitaet: Der Service nutzt `BehavioralProfileService.minActiveDaysForCapacity` als Mindest-Schwelle. Die 14-Tage-Regel wird dadurch sichergestellt, dass das Profil bei < 5 aktiven Tagen `nil` zurueckgibt. Zusaetzlich wird im Service geprueft ob die berechneten Werte aus mindestens 14 Tagen stammen. Da `BehavioralProfile` kein `activeDayCount`-Feld hat, wird ein pragmatischer Ansatz gewaehlt: Die Warnung ist nur aktiv, wenn `avgTasksPerDay >= 1.0` (impliziert genug Datenpunkte).
3. `plannedTasks = tasks.count`
4. `plannedMinutes = tasks.map(\.effectiveDuration).reduce(0, +)`
5. Ueberschreitungs-Check:
   - Tasks: `plannedTasks > Int((avgTasks * 1.5).rounded())` — 50% Puffer um false positives zu vermeiden
   - Minuten: `plannedMinutes > Int((avgMinutes * 1.5).rounded())`
6. Wenn mindestens eine Bedingung zutrifft: `LimitationWarning(...)` zurueckgeben.

**Hinweis zur 14-Tage-Regel:** `BehavioralProfileService.computeAvgTasksPerDay` gibt `nil` zurueck wenn weniger als `minActiveDaysForCapacity` (= 5) aktive Tage vorliegen. Der Schwellwert von 14 aktiven Tagen wird in `LimitationGuardService` durch eine eigene Konstante (`minActiveDaysBeforeWarning = 14`) und einen zusaetzlichen Guard auf `avgTasksPerDay >= 1.0` angenaehert. Eine praezise 14-Tage-Pruefung erfordert ein zukuenftiges Feld `activeDayCount` in `BehavioralProfile`.

### Banner-View

```swift

/// Wird in NextUpSection und MorningCoachingSection eingebettet.
struct LimitationWarningBanner: View {
    let warning: LimitationWarning
    let onDismiss: () -> Void

    var body: some View {
        // HStack mit Warn-Icon (exclamationmark.triangle), Text, Dismiss-Button (xmark)
        // Hintergrund: .orange.opacity(0.12) mit RoundedRectangle cornerRadius 10
        // Kein fullscreen overlay, kein sheet, kein alert
    }
}
```

**Banner-Text (formatiert):**
```
"Du hast dir {plannedTasks} Tasks / {plannedMinutesFormatted} vorgenommen.
Dein Schnitt liegt bei {avgTasksFormatted} Tasks / {avgMinutesFormatted}."
```
Beispiel: "Du hast dir 8 Tasks / 4 Std vorgenommen. Dein Schnitt liegt bei 4 Tasks / 2 Std."

Formatierung:
- Tasks: Integer, keine Dezimalstellen
- Minuten < 60: "{n} Min"
- Minuten >= 60: "{h} Std {m} Min" (z.B. "2 Std 30 Min") oder bei ganzen Stunden "2 Std"

### Datenfluss in DayView

```swift
// Neue State-Variable:
@State private var limitationWarningDismissed: Bool = false

// Computed Property:
private var activeLimitationWarning: LimitationWarning? {
    guard !limitationWarningDismissed else { return nil }
    // profile wird in loadMorningData() berechnet und in @State gehalten
    return LimitationGuardService.evaluate(tasks: nextUpTasks, profile: behavioralProfile)
}
```

DayView haelt zudem ein neues `@State private var behavioralProfile: BehavioralProfile?` um das Profil nach `loadMorningData()` verfuegbar zu machen (derzeit wird es nur lokal in der Funktion benutzt).

`limitationWarningDismissed` wird auf `false` zurueckgesetzt wenn sich `nextUpTasks.count` aendert (via `.onChange(of: nextUpTasks.count)`), damit die Warnung bei jeder neuen Ueberschreitung erneut erscheint.

## Expected Behavior

- **Input:** `[PlanItem]` (aktuelle Next-Up-Tasks) + `BehavioralProfile` (historische Daten)
- **Output:** `LimitationWarning?` — nil wenn keine Warnung noetig, sonst befuelltes Struct
- **Schwellwert:** 1.5x des historischen Durchschnitts (50% Puffer), sowohl fuer Tasks als auch Minuten
- **Sichtbarkeit:** Banner erscheint in NextUpSection (Daytime-Modus) UND in MorningCoachingSection (Morning-Modus)
- **Dismiss:** User tippt X → `limitationWarningDismissed = true` → Banner verschwindet
- **Re-trigger:** Wenn User weiteren Task zu Next Up hinzufuegt (`.onChange(of: nextUpTasks.count)`) → `limitationWarningDismissed = false` → Warnung erscheint erneut wenn Schwellwert noch ueberschritten
- **Keine Warnung wenn:** Profil-Daten nil (< 5 aktive Tage), oder Durchschnitt nicht ueberschritten, oder bereits dismissed (bis naechster Task hinzugefuegt wird)
- **Side effects:** Keine persistenten Zustandsaenderungen — Dismiss-State ist `@State` (in-memory, wird bei App-Neustart zurueckgesetzt)

## Known Limitations

- Die 14-Tage-Wartezeit wird nicht exakt enforced — `BehavioralProfileService` gibt erst ab 5 aktiven Tagen Daten zurueck. Exakte 14-Tage-Pruefung erfordert ein `activeDayCount`-Feld in `BehavioralProfile` (zukuenftiges Backlog-Item).
- Dismiss-State ist `@State` (in-memory). Wird die App beendet und neu gestartet, erscheint die Warnung erneut. Das ist akzeptables Verhalten fuer V1.
- Der 1.5x-Schwellwert ist hartcodiert. Kein User-Setting vorgesehen.
- `MorningCoachingSection` zeigt die Warnung basierend auf bereits bestaetigten Next-Up-Tasks — Vorschlaege (noch nicht bestaetigt) zaehlen nicht. Das ist korrekt, da `nextUpTasks` in DayView separate State-Variable ist.
