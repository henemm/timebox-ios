# RW_4.1 Soft Evening Reset — Implementation Spec

## Approval

- [ ] Approved

## Purpose

`EveningResetService` runs at every app start and silently moves unfinished Next-Up tasks back to the backlog when the calendar date has changed since the last reset. It also clears past `scheduledDate` values so the morning always presents a clean slate. No UI is shown; idempotency is guaranteed via `AppSettings.lastResetDate`.

## Implementation Details

### 1. AppSettings.swift — New Properties

Add two properties in a new `// MARK: - Evening Reset` section, following the same `@AppStorage` pattern as `nudgeLastDate`:

```swift
// MARK: - Evening Reset

/// ISO-8601 date string of the last successful reset (e.g. "2026-03-25").
/// Empty string = never reset. Used for idempotency (same pattern as nudgeLastDate).
@AppStorage("lastResetDate") var lastResetDate: String = ""

/// Hour of day at which the reset threshold is crossed (0-23, default 0 = midnight).
/// A value of 5 means: "a new day starts at 05:00" for reset purposes.
@AppStorage("resetHour") var resetHour: Int = 0
```

### 2. EveningResetService.swift — Full Implementation

```swift
import Foundation
import SwiftData

/// Silently resets unfinished Next-Up tasks and clears past scheduled dates
/// on the first app start of each new calendar day.
///
/// Design decisions:
/// - @MainActor enum: zero-allocation type, all SwiftData access on main actor
/// - Idempotency: ISO date string comparison (same pattern as AppSettings.nudgeLastDate)
/// - Single modelContext.save() after all mutations (same pattern as SyncEngine bulk-update)
/// - Returns modified count so callers can log/assert in tests
@MainActor
enum EveningResetService {

    /// Performs the daily reset if today differs from AppSettings.lastResetDate.
    ///
    /// - Parameter context: The main ModelContext (must be on @MainActor).
    /// - Returns: Number of tasks modified (0 = already reset today, nothing changed).
    /// - Throws: SwiftData fetch/save errors.
    @discardableResult
    static func performResetIfNeeded(context: ModelContext) throws -> Int {
        let settings = AppSettings.shared
        let today = isoString(for: Date(), resetHour: settings.resetHour)

        // Idempotency guard: already reset today
        guard settings.lastResetDate != today else { return 0 }

        var modifiedCount = 0
        let now = Date()

        // --- Pass 1: Clear Next-Up status from all unfinished Next-Up tasks ---
        let nextUpDescriptor = FetchDescriptor<LocalTask>(
            predicate: #Predicate { $0.isNextUp == true && $0.isCompleted == false }
        )
        let nextUpTasks = try context.fetch(nextUpDescriptor)
        for task in nextUpTasks {
            task.isNextUp = false
            task.nextUpSortOrder = nil          // mirror SyncEngine.updateNextUp() contract
            task.assignedFocusBlockID = nil     // Bug 52 pattern: clear stale block assignment
            task.rescheduleCount += 1
            task.modifiedAt = now
            modifiedCount += 1
        }

        // --- Pass 2: Clear scheduledDate that lies before today's start ---
        let startOfDay = Calendar.current.startOfDay(for: now)
        let scheduledDescriptor = FetchDescriptor<LocalTask>(
            predicate: #Predicate { $0.scheduledDate != nil && $0.isCompleted == false }
        )
        let scheduledTasks = try context.fetch(scheduledDescriptor)
        for task in scheduledTasks {
            guard let date = task.scheduledDate, date < startOfDay else { continue }
            task.scheduledDate = nil
            task.scheduledDuration = nil
            task.modifiedAt = now
            modifiedCount += 1
        }

        // --- Persist all mutations in one save ---
        if modifiedCount > 0 {
            try context.save()
        }

        // --- Record reset date (even if 0 tasks changed — still counts as done) ---
        settings.lastResetDate = today

        return modifiedCount
    }

    // MARK: - Private Helpers

    /// Returns the ISO-8601 date string ("yyyy-MM-dd") for the logical "day"
    /// the given date belongs to, taking resetHour into account.
    ///
    /// Example: resetHour=5, date=2026-03-26T03:00 → "2026-03-25"
    /// (still the previous day until 05:00)
    private static func isoString(for date: Date, resetHour: Int) -> String {
        let adjusted: Date
        if resetHour > 0 {
            // Subtract resetHour hours so the boundary shifts forward
            adjusted = Calendar.current.date(
                byAdding: .hour, value: -resetHour, to: date
            ) ?? date
        } else {
            adjusted = date
        }
        let formatter = ISO8601DateFormatter()
        formatter.formatOptions = [.withFullDate]
        formatter.timeZone = Calendar.current.timeZone
        return formatter.string(from: Calendar.current.startOfDay(for: adjusted))
    }
}
```

### 3. FocusBloxApp.swift — iOS Trigger

Insert inside the existing `onAppear` cleanup block, after `RecurrenceService.repairOrphanedRecurringSeries` and before background async tasks, following the same `!ProcessInfo.processInfo.arguments.contains("-UITesting")` guard already present:

```swift
// RW_4.1: Soft Evening Reset — clear unfinished Next-Up tasks on new calendar day
let resetCount = (try? EveningResetService.performResetIfNeeded(
    context: sharedModelContainer.mainContext
)) ?? 0
if resetCount > 0 {
    Task {
        await SmartNotificationEngine.reconcile(
            reason: .taskChanged,
            container: sharedModelContainer,
            eventKitRepo: eventKitRepository
        )
    }
}
```

Note: The `SmartNotificationEngine.reconcile` call is placed in the app entry point (not inside `EveningResetService`) to keep the service free of cross-cutting concerns — consistent with how reconcile is already triggered in `onChange(of: scenePhase)`.

## Expected Behavior

- **Input:** `ModelContext` (main context), `AppSettings.shared` state (read implicitly)
- **Output:** `Int` — count of tasks modified; `0` if already reset today
- **Side effects:**
  - Mutates `LocalTask` fields: `isNextUp`, `nextUpSortOrder`, `assignedFocusBlockID`, `rescheduleCount`, `scheduledDate`, `scheduledDuration`, `modifiedAt`
  - Calls `modelContext.save()` once if any tasks changed
  - Sets `AppSettings.shared.lastResetDate` to today's ISO string
  - Does NOT delete any tasks — status-only mutations

### Idempotency Contract

The service compares `AppSettings.shared.lastResetDate` (ISO string) to today's logical date string before doing any work. A second call on the same logical day returns `0` immediately without touching the store.

### resetHour Behavior

With `resetHour = 0` (default), "today" is the calendar day of `Date()`. With `resetHour = 5`, an app launch at 03:00 on March 26 is still considered "March 25" — the reset that would have fired at midnight is deferred until the user opens the app after 05:00.

### Timezone Safety

Day boundaries are computed via `Calendar.current.startOfDay(for:)`, which respects the device's current timezone. Absolute UTC timestamps are never compared directly.

### CloudKit Sync

`modifiedAt = now` is set on every mutated task. This satisfies the CloudKit change detection mechanism used throughout the codebase (same pattern as `SyncEngine.updateDiscipline`, `SyncEngine.scheduleTask`, etc.).

## Known Limitations

- `resetHour` is stored in `AppSettings` but not yet exposed in any Settings UI — it defaults to `0` and can only be changed via direct `UserDefaults` manipulation (intentionally out of scope for RW_4.1).
- BGAppRefreshTask night-reset is explicitly out of scope. App-start is the reliable trigger path per the feature spec. Background refresh is a future enhancement.
- A task that is both `isNextUp=true` AND has a past `scheduledDate` will be modified in both passes (Pass 1 and Pass 2) but `modifiedAt` is set once per task (the second write just overwrites with the same `now` value — harmless).
