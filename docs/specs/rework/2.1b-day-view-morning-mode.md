# RW_2.1b — DayView Phase B: Morning Mode

## Approval

- [ ] Approved

## Purpose

Replaces the morning placeholder in DayView with real content: a compact calendar overview, visually highlighted free time gaps (via GapFinder), and "Next Up" tasks that could fill those gaps. This is the first phase of making the morning tab genuinely useful as a daily planning surface.

## Implementation Details

### Part A — New State and Environment

Add to `DayView`:

```swift
import SwiftData

// Environments
@Environment(\.eventKitRepository) private var eventKitRepo
@Environment(\.modelContext) private var modelContext

// State
@State private var calendarEvents: [CalendarEvent] = []
@State private var focusBlocks: [FocusBlock] = []
@State private var nextUpTasks: [PlanItem] = []
@State private var freeSlots: [TimeSlot] = []
@State private var isLoading = false
@State private var isPermissionDenied = false
```

Attach to NavigationStack:

```swift
.task { if phase == .morning { await loadMorningData() } }
```

### Part B — morningContent View (4 states in order)

```
1. isLoading        → ProgressView("Lade Kalender...")
2. isPermissionDenied → ContentUnavailableView("Kein Kalender-Zugriff", ...)
                         + Settings button gated with #if os(iOS)
3. content is empty → ContentUnavailableView("Keine Vorschlaege",
                         description: "Plan deinen Tag selbst")
                         + NavigationLink to Backlog tab
4. has content      → ScrollView { VStack {
                           Section: calendarEvents (list of time + title)
                           Section: freeSlots (highlighted, e.g. .yellow background)
                           Section: nextUpTasks (title + estimated duration)
                       }}
```

Empty state is triggered when `calendarEvents.isEmpty && nextUpTasks.isEmpty`.

### Part C — loadMorningData()

Pattern mirrors BlockPlanningView:

```swift
private func loadMorningData() async {
    isLoading = true
    do {
        let hasAccess = try await eventKitRepo.requestAccess()
        guard hasAccess else {
            isPermissionDenied = true
            isLoading = false
            return
        }
        calendarEvents = try eventKitRepo.fetchCalendarEvents(for: Date())
        focusBlocks = try eventKitRepo.fetchFocusBlocks(for: Date())

        let taskSource = LocalTaskSource(modelContext: modelContext)
        let syncEngine = SyncEngine(taskSource: taskSource, modelContext: modelContext)
        let allTasks = try await syncEngine.sync()
        nextUpTasks = allTasks.filter { $0.isNextUp && !$0.isCompleted && $0.isActionable }

        let scheduledPairs = allTasks
            .filter { $0.isScheduled }
            .map { (
                start: $0.scheduledDate!,
                end: $0.scheduledDate!.addingTimeInterval(
                    Double($0.scheduledDuration ?? $0.estimatedDuration ?? 30) * 60
                )
            )}
        freeSlots = GapFinder(
            events: calendarEvents,
            focusBlocks: focusBlocks,
            scheduledTasks: scheduledPairs,
            date: Date()
        ).findFreeSlots(minMinutes: 30, maxMinutes: 60)
    } catch {
        // Silently fail — view remains in empty state
    }
    isLoading = false
}
```

`cleanOrphanedBlockAssignments` is not called — this view is read-only.

### Cross-Platform Note

`UIApplication.openSettingsURLString` is iOS-only. The Settings button in the permission-denied state must be guarded:

```swift
#if os(iOS)
Button("Einstellungen oeffnen") {
    UIApplication.shared.open(URL(string: UIApplication.openSettingsURLString)!)
}
#endif
```

Everything else in DayView.swift is shared code and compiles on both platforms unchanged.

## Expected Behavior

- **Input:** User opens the app in the morning (DayPhase == .morning). DayView is the active tab.
- **Output:** A scroll view showing today's calendar events, visually highlighted free time slots (>=30 min), and up to N "Next Up" tasks that could fill those slots.
- **Loading state:** ProgressView shown while data is fetching; replaced by content or error state when done.
- **Permission denied:** ContentUnavailableView with explanation text + Settings deep-link (iOS only).
- **Empty state:** ContentUnavailableView with text "Keine Vorschlaege — plan deinen Tag selbst" and a navigation link to the Backlog tab.
- **Side effects:** None. This view is read-only — no tasks are created, modified, or deleted.

## Known Limitations

- No AI-powered suggestions (NextUpSuggestionService does not exist yet — planned for RW_2.2). Only existing "Next Up" tasks are displayed.
- GapFinder uses a 30–60 minute window. Gaps shorter than 30 minutes are not shown even if they exist.
- Data is loaded once on `.task` — no pull-to-refresh in Phase B.
- macOS cannot deep-link to Settings; the permission-denied state shows the message but no action button on macOS.
- Phase changes during the same session do not trigger a reload (`.task` fires once per view appearance).
