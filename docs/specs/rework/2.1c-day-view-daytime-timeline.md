# RW_2.1c — DayView Phase C: Tages-Timeline (TimelineView Integration)

## Approval

- [ ] Approved

## Purpose

Replaces the daytime placeholder ("Timeline kommt bald") in DayView with the existing TimelineView component. Shows a full-day timeline (6:00–22:00) with calendar events, focus blocks, and scheduled tasks — read-only, no drag-and-drop. This makes the "Tag" tab useful during the day, not just in the morning.

## Implementation Details

### Part A — New State Variable

Add to existing DayView state:

```swift
@State private var scheduledTasks: [TimelineItem] = []
```

All other state variables (calendarEvents, focusBlocks, isLoading, isPermissionDenied) already exist from Phase B.

### Part B — daytimeContent View (4 states)

Replace the ContentUnavailableView placeholder with:

```
1. isLoading          → ProgressView("Lade Timeline...")
2. isPermissionDenied → permissionDeniedContent (reuse from morning — already exists)
3. no data            → ContentUnavailableView("Keine Termine",
                           systemImage: "calendar",
                           description: "Dein Tag ist frei")
4. has data           → TimelineView(
                           date: Date(),
                           events: calendarEvents,
                           scheduledTasks: scheduledTasks
                         )
                         // All callbacks nil = read-only mode
```

Empty state triggers when `calendarEvents.isEmpty && scheduledTasks.isEmpty`.

### Part C — loadDaytimeData()

Pattern mirrors loadMorningData() but simpler (no GapFinder, no nextUpTasks):

```swift
private func loadDaytimeData() async {
    isLoading = true
    defer { isLoading = false }

    do {
        let hasAccess = try await eventKitRepo.requestAccess()
        guard hasAccess else {
            isPermissionDenied = true
            return
        }
        calendarEvents = try eventKitRepo.fetchCalendarEvents(for: Date())
        focusBlocks = try eventKitRepo.fetchFocusBlocks(for: Date())

        let taskSource = LocalTaskSource(modelContext: modelContext)
        let syncEngine = SyncEngine(taskSource: taskSource, modelContext: modelContext)
        let allTasks = try await syncEngine.sync()

        scheduledTasks = allTasks
            .filter { $0.isScheduled && Calendar.current.isDateInToday($0.scheduledDate!) }
            .map { task in
                TimelineItem(
                    scheduledTaskID: task.id,
                    title: task.title,
                    scheduledDate: task.scheduledDate!,
                    durationMinutes: task.scheduledDuration ?? task.estimatedDuration ?? 30
                )
            }
    } catch {
        // Silently fail — view remains in empty state
    }
}
```

### Part D — Extend .task Trigger

Update the existing `.task` modifier to also load daytime data:

```swift
.task {
    switch phase {
    case .morning: await loadMorningData()
    case .daytime: await loadDaytimeData()
    case .evening: break
    }
}
```

Add `.refreshable` to daytimeContent for pull-to-refresh:

```swift
TimelineView(...)
    // refreshable is already built into TimelineView via onRefresh callback
```

Pass `onRefresh: { await loadDaytimeData() }` to enable pull-to-refresh.

### Part E — UI Tests (DayViewUITests.swift)

New tests:

- `test_daytimeMode_showsTimeline` — Timeline grid visible during daytime hours
- `test_daytimeMode_showsCalendarEvents` — Calendar events rendered on timeline
- `test_daytimeMode_showsScheduledTasks` — Scheduled tasks rendered as orange blocks
- `test_daytimeMode_showsEmptyState` — Empty state when no events/tasks
- `test_daytimeMode_permissionDenied` — Permission denied shows message + settings button

All tests use mock/launch argument injection to control the phase (force daytime mode regardless of actual time).

### Cross-Platform Note

Everything in DayView.swift is shared code. TimelineView compiles on both iOS and macOS. No platform-specific guards needed for the daytime content (unlike morning's Settings button which uses `#if os(iOS)`).

## Expected Behavior

- **Input:** User opens DayView during daytime hours (between morningEndHour and eveningStartHour, default 12:00–18:00).
- **Output:** A scrollable timeline showing the full day (6:00–22:00) with calendar events as colored blocks, focus blocks with task assignments, and scheduled tasks as orange blocks.
- **Loading state:** ProgressView shown while data is fetching.
- **Permission denied:** Same as morning mode — ContentUnavailableView + Settings button (iOS).
- **Empty state:** "Keine Termine — Dein Tag ist frei" when no events and no scheduled tasks.
- **Pull-to-refresh:** Supported via TimelineView's built-in refreshable.
- **Read-only:** No drag-and-drop, no scheduling, no context menu actions. Pure viewing.
- **Side effects:** None. This view is read-only.

## Known Limitations

- No drag-and-drop scheduling from DayView (planned for RW_3+ integration)
- No event tap actions (no detail sheet or editing)
- Phase changes during same session don't auto-reload (`.task` fires once per appearance)
- Current time indicator ("now line") not included (potential future enhancement)
- FocusBlocks appear as calendar events on the timeline (they are calendar events with focusBlock:true metadata)
