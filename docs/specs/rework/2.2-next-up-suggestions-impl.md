# RW_2.2 — NextUpSuggestionService: Implementation Spec

## Approval

- [ ] Approved

## Purpose

Generates 3-5 task suggestions each morning by matching open tasks to free calendar gaps using deterministic scoring (priorityScore × timeAffinityBonus × rescheduleBonus). Suggestions surface in DayView via a new MorningCoachingSection; tapping confirms a task as Next Up + scheduled, swiping dismisses it.

## Source

- **File:** `Sources/Services/NextUpSuggestionService.swift` (new)
- **Identifier:** `enum NextUpSuggestionService`

## Implementation Details

### NextUpSuggestionService

Pattern: `enum` with `static` methods, identical to `BehavioralProfileService`.

```swift
enum NextUpSuggestionService {

    // MARK: - Cache
    nonisolated(unsafe) private static var _cache: CacheEntry?

    // MARK: - Public API

    /// Returns cached suggestions or computes fresh ones.
    /// Cache is day-scoped: invalidated if stored date != today.
    static func suggestions(
        items: [PlanItem],
        slots: [TimeSlot],
        profile: BehavioralProfile,
        calendarEvents: [CalendarEvent],
        now: Date = Date()
    ) -> [NextUpSuggestion]

    /// Clears the in-memory cache.
    /// Must be called when any PlanItem changes isNextUp, isCompleted, or rescheduleCount.
    static func invalidateCache()

    // MARK: - Internal (internal for unit-testability)

    static func compute(
        items: [PlanItem],
        slots: [TimeSlot],
        profile: BehavioralProfile,
        calendarEvents: [CalendarEvent],
        now: Date
    ) -> [NextUpSuggestion]

    static func score(
        item: PlanItem,
        slot: TimeSlot,
        profile: BehavioralProfile,
        now: Date
    ) -> Double

    static func meetingLoadForToday(
        events: [CalendarEvent],
        date: Date
    ) -> MeetingLoad

    static func maxSuggestionsForLoad(_ load: MeetingLoad) -> Int
}
```

### Scoring Algorithm

```
finalScore = Double(priorityScore)        // base: 0-100
           × timeAffinityBonus             // 0.5 – 1.5
           × rescheduleBonus               // 1.0 – 1.5
```

**timeAffinityBonus**
- Determine `DayPeriod` of `slot.startDate` (morning / afternoon / evening via `BehavioralProfileService.dayPeriod(for:)`)
- Look up `profile.categoryTimeAffinity?[category]?[period]`
  - Found (value `v` in 0.0-1.0): `bonus = 0.5 + v`  → range **0.5-1.5**
  - Not found (nil profile or unknown category): `bonus = 1.0` (neutral)

**rescheduleBonus**
- `count = item.rescheduleCount`
  - 0: `1.0`
  - 1-2: `1.1`
  - 3-4: `1.25`
  - 5+: `1.5`

**Example concrete values:**
| priorityScore | timeAffinity | rescheduleCount | finalScore |
|---|---|---|---|
| 80 | 0.9 (→ 1.4) | 0 (→ 1.0) | 112.0 |
| 60 | 0.5 (→ 1.0) | 3 (→ 1.25) | 75.0 |
| 40 | 0.2 (→ 0.7) | 0 (→ 1.0) | 28.0 |
| 50 | nil (→ 1.0) | 5 (→ 1.5) | 75.0 |

### Candidate Filtering (before scoring)

A `PlanItem` is eligible for suggestion only when **all** of the following hold:

1. `!item.isCompleted`
2. `item.isActionable` (i.e. `!item.isBlocked`)
3. `!item.isNextUp` (already staged — skip)
4. `item.estimatedDuration != nil`
5. `item.estimatedDuration! <= slot.durationMinutes`

### Selection Algorithm (compute)

```
For each slot in slots (chronological order):
  1. Filter eligible candidates for this slot
  2. Score each candidate
  3. Pick the highest-scoring candidate
  4. Add as NextUpSuggestion if not already selected for an earlier slot
  5. Remove chosen item from candidate pool (prevent duplicate suggestions)

Limit result to maxSuggestions (see Meeting-Load Cap below)
```

### Meeting-Load Cap

```swift
static func maxSuggestionsForLoad(_ load: MeetingLoad) -> Int {
    switch load {
    case .low:    return 5
    case .medium: return 4
    case .high:   return 3
    }
}
```

Total duration guard: after selection, drop trailing suggestions if cumulative `estimatedDuration` would exceed `slots.map(\.durationMinutes).reduce(0,+)`.

### Cache Strategy

- `suggestions(...)` checks `_cache`:
  - Cache hit: `Calendar.current.isDate(cached.date, inSameDayAs: now)` → return cached
  - Cache miss or stale date → call `compute(...)`, store new `CacheEntry`
- `invalidateCache()` sets `_cache = nil`
- **Who calls invalidateCache:** `DayView.loadMorningData()` must call it when `SyncEngine.updateNextUp()` or a task mutation occurs (handled via existing `onChange` pattern on `planItems`)

## MorningCoachingSection — View Contract

```swift
/// Sources/Views/MorningCoachingSection.swift
struct MorningCoachingSection: View {
    let suggestions: [NextUpSuggestion]
    let onConfirm: (NextUpSuggestion) -> Void   // called on tap confirm
    let onDismiss: (NextUpSuggestion) -> Void   // called on swipe dismiss
}
```

**Accessibility IDs:**
- Section container: `.accessibilityIdentifier("morningCoachingSection")`
  - Must use `.accessibilityElement(children: .contain)`
- Each row: `.accessibilityIdentifier("suggestionRow_\(suggestion.id)")`
- Confirm button inside row: `.accessibilityIdentifier("confirmSuggestion_\(suggestion.id)")`

**Empty state:** When `suggestions.isEmpty` the section renders nothing (zero height), never a placeholder message. DayView decides whether to show the section at all.

**Row content (minimum):**
- Task title
- Slot time range (e.g. "09:00 – 09:30")
- Estimated duration
- Confirm button (checkmark)
- Dismiss button (X icon, `.xmark.circle.fill`)

> Note: Originally specified as swipe-to-dismiss (`.swipeActions`), changed to tap button because `.swipeActions` only works inside `List`/`Form` — not in `ScrollView > VStack`.

**Dismiss** removes the row locally (no persistence); the suggestion is not re-shown until the next day (handled by daily cache).

## DayView Integration Points

File: `Sources/Views/DayView.swift`

Three surgical changes (~25 LoC total):

1. **State variable** (add near other `@State` declarations):
   ```swift
   @State private var morningSuggestions: [NextUpSuggestion] = []
   ```

2. **loadMorningData() extension** (after existing GapFinder call):
   ```swift
   // Reuse already-computed `freeSlots` and `behavioralProfile` from existing loadMorningData
   morningSuggestions = NextUpSuggestionService.suggestions(
       items: planItems,
       slots: freeSlots,
       profile: behavioralProfile,
       calendarEvents: calendarEvents,
       now: Date()
   )
   ```

3. **Morning-mode body** (add MorningCoachingSection before or after existing NextUpSection):
   ```swift
   if !morningSuggestions.isEmpty {
       MorningCoachingSection(
           suggestions: morningSuggestions,
           onConfirm: { suggestion in
               try? syncEngine.updateNextUp(itemID: suggestion.id, isNextUp: true)
               NextUpSuggestionService.invalidateCache()
               morningSuggestions.removeAll { $0.id == suggestion.id }
           },
           onDismiss: { suggestion in
               morningSuggestions.removeAll { $0.id == suggestion.id }
           }
       )
   }
   ```

> Note: `behavioralProfile` and `freeSlots` must already be in scope from RW_2.1b's `loadMorningData`. If not yet populated as local variables, extract them from the existing GapFinder/BehavioralProfileService call sites in that method.

## Expected Behavior

- **Input:** `[PlanItem]` (open tasks), `[TimeSlot]` (free gaps from GapFinder), `BehavioralProfile`, `[CalendarEvent]`
- **Output:** `[NextUpSuggestion]` (0-5 items, sorted by slot start time for display)
- **Side effects:** Writes to in-memory `_cache`; none on disk
- **Performance:** < 200ms — all operations are O(n×m) over small arrays (< 200 tasks, < 10 slots)

---

## Known Limitations

- Tasks without `estimatedDuration` are silently skipped; no error or fallback duration
- `BehavioralProfile` may be `nil` for new users (< 10 completed tasks) — `timeAffinityBonus` defaults to 1.0, which is safe
- Cache is process-scoped (in-memory); a fresh app launch always recomputes
- `MorningCoachingSection` dismiss is session-only; dismissed suggestions reappear after app restart within the same calendar day (cache still returns them)
