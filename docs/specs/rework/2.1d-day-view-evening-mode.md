# RW_2.1d — DayView Phase D: Abend-Modus (Evening Mode)

## Approval

- [ ] Approved

## Purpose

Replaces the evening placeholder ("Reflexion kommt bald") in DayView with a real Tagesrueckblick — a daily wrap-up showing completed tasks, unfinished tasks, and a compact visual day timeline. Stub cards for the upcoming RW_4.2 (Success Story) and RW_4.3 (Failure Protocol) are included as locked placeholders, making the evening mode genuinely useful while keeping the scope small.

### Part D — loadEveningData()

Pattern mirrors loadMorningData() and loadDaytimeData():

```swift
private func loadEveningData() async {
    isLoading = true
    defer { isLoading = false }

    do {
        let hasAccess = try await eventKitRepo.requestAccess()
        guard hasAccess else {
            isPermissionDenied = true
            return
        }

        calendarEvents = try eventKitRepo.fetchCalendarEvents(for: Date())
        focusBlocks = try eventKitRepo.fetchFocusBlocks(for: Date())

        let taskSource = LocalTaskSource(modelContext: modelContext)
        let syncEngine = SyncEngine(taskSource: taskSource, modelContext: modelContext)
        let allTasks = try await syncEngine.sync()

        let startOfDay = Calendar.current.startOfDay(for: Date())

        completedTasks = allTasks.filter {
            guard let completedAt = $0.completedAt else { return false }
            return completedAt >= startOfDay
        }

        unfinishedTasks = allTasks.filter {
            $0.completedAt == nil &&
            ($0.isNextUp || $0.isScheduled) &&
            ($0.scheduledDate.map { Calendar.current.isDateInToday($0) } ?? $0.isNextUp)
        }

        timelineSegments = buildSegments(
            events: calendarEvents,
            completed: completedTasks,
            unfinished: unfinishedTasks
        )
    } catch {
        // Silently fail — view stays in empty state
    }
}
```

### Part E — Segment Mapping (pure function, unit-testable)

```swift
func buildSegments(
    events: [CalendarEvent],
    completed: [PlanItem],
    unfinished: [PlanItem]
) -> [DayTimelineSegment] {
    var segments: [DayTimelineSegment] = []

    for event in events {
        let start = minutesFromMidnight(event.startDate)
        let end   = minutesFromMidnight(event.endDate)
        segments.append(DayTimelineSegment(startMinute: start, endMinute: end, kind: .calendar))
    }

    for task in completed {
        guard let date = task.completedAt else { continue }
        let start = minutesFromMidnight(date)
        let duration = task.estimatedDuration ?? 30
        segments.append(DayTimelineSegment(startMinute: start, endMinute: start + duration, kind: .completed))
    }

    for task in unfinished {
        guard let date = task.scheduledDate else { continue }
        let start = minutesFromMidnight(date)
        let duration = task.scheduledDuration ?? task.estimatedDuration ?? 30
        segments.append(DayTimelineSegment(startMinute: start, endMinute: start + duration, kind: .missed))
    }

    return segments.sorted { $0.startMinute < $1.startMinute }
}

private func minutesFromMidnight(_ date: Date) -> Int {
    let components = Calendar.current.dateComponents([.hour, .minute], from: date)
    return (components.hour ?? 0) * 60 + (components.minute ?? 0)
}
```

`buildSegments` is a free function or static method so it is directly unit-testable without a SwiftUI environment.

### Part F — DayTimelineBar (DayTimelineBar.swift)

```swift
struct DayTimelineSegment: Identifiable {
    let id = UUID()
    let startMinute: Int   // minutes from midnight, 0–1440
    let endMinute: Int
    let kind: SegmentKind

    enum SegmentKind {
        case completed  // green
        case calendar   // gray
        case missed     // orange
    }

    var color: Color {
        switch kind {
        case .completed: .green
        case .calendar:  .secondary
        case .missed:    .orange
        }
    }
}

struct DayTimelineBar: View {
    let segments: [DayTimelineSegment]

    private let totalMinutes: CGFloat = 1440

    var body: some View {
        GeometryReader { geo in
            ZStack(alignment: .leading) {
                RoundedRectangle(cornerRadius: 6)
                    .fill(Color(.systemFill))
                    .frame(height: 24)

                ForEach(segments) { seg in
                    let x = CGFloat(seg.startMinute) / totalMinutes * geo.size.width
                    let w = CGFloat(seg.endMinute - seg.startMinute) / totalMinutes * geo.size.width
                    RoundedRectangle(cornerRadius: 3)
                        .fill(seg.color)
                        .frame(width: max(w, 3), height: 24)
                        .offset(x: x)
                }
            }
        }
        .frame(height: 24)
        .accessibilityIdentifier("dayTimelineBar")
    }
}
```

No interactive elements. No `#if os()` guards needed.

## Expected Behavior

- **Input:** User opens DayView after eveningStartHour (default 18:00).
- **Output:** Scrollable Tagesrueckblick with: compact day timeline bar, completed tasks list (green), unfinished tasks list (orange), Success Story stub card (locked), Failure Quick-Select stub card (locked).
- **Loading state:** ProgressView shown while data fetches.
- **Permission denied:** Same permissionDeniedContent as morning mode (reused, no duplication).
- **Empty state:** "Noch nichts erledigt" with moon.stars icon when both lists are empty.
- **Stub cards:** Visible, non-interactive. No logic. No navigation. Purely visual placeholders.
- **Side effects:** None. Read-only view. No writes, no notifications.

## Known Limitations

- Success Story (RW_4.2) and Failure Protocol (RW_4.3) stubs are not functional — they show only locked placeholder text
- Completed tasks use `completedAt` timestamp for segment positioning; tasks without a `completedAt` (only `isNextUp` filtered) will not appear in the timeline bar
- Phase changes during the same session do not auto-reload (`.task` fires once per appearance)
- DayTimelineBar does not display a "current time" indicator
- Unfinished tasks without a `scheduledDate` (nextUp tasks not explicitly scheduled) are listed in the section but not rendered in the timeline bar
