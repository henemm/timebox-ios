# RW 1.5 — Refiner-Tab entfernen + Auto-Confirm Pipeline

## Approval

- [ ] Approved

## Purpose

Der Refiner-Tab (RW 1.2/1.3) erfordert manuelle Freigabe von KI-Vorschlaegen fuer neue Tasks. Dieses Konzept ist obsolet — neue Tasks sollen automatisch im Hintergrund angereichert werden, ohne Nutzer-Interaktion. Durch die Entfernung des Refiner-Tabs reduziert sich die Tab-Anzahl von 6 auf 5, wodurch iOS den "More"-Tab eliminiert und "Review" direkt sichtbar wird.

## Implementation Details

### Step 1 — Logik-Aenderungen (~30 LoC, 7 Dateien)

#### 1a. `LocalTaskSource.swift` — Auto-Confirm nach Enrichment

Nach Zeile 129 (`await enrichment.enrichTask(task)`) eine Zeile einfuegen:

```swift
// Auto-confirm: promote suggested* fields to main fields immediately
task.confirmSuggestions()
```

Kein weiterer Umbau noetig — `enrichTask()` ist `await`, daher keine Race Condition.

#### 1b. `LocalTask.swift` — confirmSuggestions() Guard anpassen

Die Guard-Bedingung in `confirmSuggestions()` (Zeile 297) aendern:

```swift
// VORHER:
guard lifecycleStatus == TaskLifecycleStatus.raw.rawValue else { return }

// NACHHER: Auch Tasks mit Status "active" duerfen auto-confirmed werden
// (idempotent: suggested*-Felder werden nur kopiert wenn Hauptfeld leer/nil)
// Guard entfernen — die if-let Pruefungen schuetzen bereits vor Ueberschreiben
```

Begruendung: QuickCapture-Aufrufe uebergeben ggf. kein "raw" mehr als lifecycleStatus. Die einzelnen `if`-Pruefungen (`if taskType.isEmpty`, `if importance == nil`) sind bereits idempotent.

#### 1c. `QuickCaptureView.swift` — Kein "raw" mehr

Zeile 362 aendern:

```swift

// NACHHER: Parameter entfernen (Default ist "active")
// (lifecycleStatus-Parameter komplett weglassen)
```

#### 1d. `QuickCapturePanel.swift` — Kein "raw" mehr (macOS)

## Expected Behavior

- **Input:** Nutzer erstellt Task via Quick Capture (iOS/macOS), Siri, Watch, Share Extension
- **Output:** Task wird sofort als "active" erstellt, KI-Enrichment laeuft im Hintergrund, Ergebnisse werden automatisch uebernommen — kein manueller Bestaetigungs-Schritt
- **Side effects:**
  - Tab-Bar zeigt 5 statt 6 Tabs → "More" entfaellt, "Review" direkt sichtbar
  - macOS Sidebar hat 5 statt 6 Eintraege
  - Existierende "raw" Tasks werden beim naechsten App-Start automatisch auf "active" migriert

## Known Limitations

- Tasks die offline oder ohne Apple Intelligence erstellt werden, bekommen keine KI-Attribute (Importance, Urgency, Category, Duration, Energy Level) — sie erscheinen trotzdem im Backlog, nur ohne diese Metadaten
- `TaskLifecycleStatus.raw` und `.refined` bleiben als Enum-Cases bestehen (CloudKit-Kompatibilitaet), werden aber nicht mehr aktiv genutzt
- `suggested*`-Felder bleiben auf dem Model bestehen (harmlos, werden weiterhin von Enrichment beschrieben)
