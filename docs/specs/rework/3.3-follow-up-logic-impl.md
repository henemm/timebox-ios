# RW_3.3: Follow-up Logic — Implementierungs-Spec

## Approval

- [ ] Approved

## Purpose

Beim Abbruch eines Focus Blocks den Fortschritt festhalten und automatisch eine Anschlussaufgabe erstellen. Der User soll optional beschreiben koennen wie weit er gekommen ist. Die Anschlussaufgabe erbt Metadaten und berechnet die Restdauer.

## Akzeptanzkriterien (aus Story-Spec)

- [ ] Bei Abbruch: "Wie weit bist du?" (Freitext, optional)
- [ ] Automatische Anschlussaufgabe: "Weiter: [Original-Titel]"
- [ ] Erbt: Kategorie, Importance, Tags
- [ ] Restdauer = Original minus abgelaufen (Minimum 15 Min.)
- [ ] Landet im Backlog mit `lifecycleStatus = .active`
- [ ] Follow-up-Kette: Verweist immer auf ORIGINAL-Task (flach, kein Baum)

### 2. FocusBlockActionService.swift — Neue Methode

```swift
// Neuer Case in TaskActionResult:
case abortedWithFollowUp(newTaskID: String)

// Neue Methode:
@MainActor
static func abortWithFollowUp(
    taskID: String,
    block: FocusBlock,
    progressNote: String?,
    modelContext: ModelContext
) throws -> TaskActionResult {
    // 1. Original-Task laden
    let descriptor = FetchDescriptor<LocalTask>()
    guard let allTasks = try? modelContext.fetch(descriptor),
          let original = allTasks.first(where: { $0.id == taskID }) else {
        return .completed // Fallback
    }

    // 2. progressNote auf Original schreiben (optional)
    if let note = progressNote, !note.isEmpty {
        original.progressNote = note
    }

    // 3. Original zurueck ins Backlog (NICHT als completed markieren)
    original.assignedFocusBlockID = nil
    original.isNextUp = false
    original.modifiedAt = Date()

    // 4. Restdauer berechnen
    let elapsedSeconds = block.taskTimes[taskID] ?? 0
    let elapsedMinutes = elapsedSeconds / 60
    let originalDuration = original.estimatedDuration ?? 60
    let remainingDuration = max(15, originalDuration - elapsedMinutes)

    // 5. Follow-up erstellen
    let followUp = LocalTask(
        title: "Weiter: \(original.title)",
        importance: original.importance,
        tags: original.tags,
        estimatedDuration: remainingDuration,
        urgency: original.urgency,
        taskType: original.taskType,
        taskDescription: original.taskDescription,
        lifecycleStatus: "active"
    )

    // 6. Flache Kette: immer auf Root-Task verweisen
    followUp.parentTaskID = original.parentTaskID ?? original.id

    // 7. Persistieren
    modelContext.insert(followUp)
    try? modelContext.save()

    return .abortedWithFollowUp(newTaskID: followUp.id)
}
```

**Flache-Kette-Regel:** Wenn Original selbst ein Follow-up ist (`parentTaskID != nil`), erbt der neue Task diesen parentTaskID (= Root). Wenn Original kein Follow-up ist, wird `original.id` zum parentTaskID. So entsteht nie ein Baum.

**createFollowUp()-Methode:**
```swift
private func createFollowUp(for task: PlanItem) {
    Task {
        let result = try? FocusBlockActionService.abortWithFollowUp(
            taskID: task.id,
            block: block,
            progressNote: progressNotes[task.id],
            modelContext: modelContext
        )
        if case .abortedWithFollowUp = result {
            withAnimation { followUpCreated.insert(task.id) }
        }
    }
}
```

## Expected Behavior

- **Input:** User drueckt "Abbrechen" waehrend aktivem Focus Block
- **Output:** Sprint Review oeffnet sich mit Abbruch-Kontext. Pro unerledigtem Task: optionaler Freitext + Follow-up-Button. Follow-up-Task landet im Backlog.
- **Side effects:**
  - Original-Task bekommt `progressNote` (wenn eingegeben)
  - Original-Task wird zurueck ins Backlog geschoben (`assignedFocusBlockID = nil`)
  - Neuer Task "Weiter: [Titel]" mit Restdauer im Backlog
  - `parentTaskID` auf dem neuen Task verweist auf Root-Original

## Regulaerer Sprint Review (isAborted = false)

Keine Aenderung am bestehenden Verhalten. SprintReviewSheet funktioniert wie bisher — die Follow-up-UI ist nur sichtbar wenn `isAborted == true`.

## Known Limitations

- Kein automatisches Verkuerzen der Block-Endzeit bei Abbruch (Block laeuft im Kalender weiter)
- Freitext-Notiz ist einmalig — kein Editieren nach Erstellung
- Follow-up wird pro Task einzeln erstellt (kein "Alle Follow-ups erstellen"-Button)
