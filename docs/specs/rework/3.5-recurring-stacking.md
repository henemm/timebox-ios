# RW_3.5 — Recurring Stacking: Visuelle Gruppierung + Priority Boost

> Status: Skizze (noch nicht approved)

## Problem

Wenn ein User eine wiederkehrende Aufgabe mehrfach nicht erledigt, entstehen mehrere offene Instanzen derselben Serie. Diese erscheinen aktuell als **separate, unverbundene Zeilen** im Backlog — ohne Hinweis dass sie zusammengehoeren. Die Prioritaet steigt nicht mit der Anzahl aufgelaufener Instanzen.

## User-Erwartung

Wenn "Waesche waschen" 3x aufgelaufen ist, will der User **einen** Eintrag mit Badge "x3" sehen — nicht 3 separate Zeilen. Die Aufgabe soll automatisch hoeher rutschen. Beim Abhaken sinkt die Zahl auf x2, nicht alles weg.

### Gewuenschtes Verhalten

- **x1:** Normale Darstellung, kein Badge
- **x2:** Leicht hervorgehoben, Badge "x2"
- **x3+:** Deutlich warm/kraeftig hervorgehoben, Badge zeigt Anzahl
- Beim Abhaken: Aelteste Instanz wird erledigt, Zaehler sinkt um 1
- Wenn letzte Instanz erledigt: Badge verschwindet, normale Darstellung
- Aufgelaufene Serien rutschen automatisch in der Liste nach oben

### Was den User verwirren koennte

- Alle Instanzen auf einmal verschwinden beim Abhaken (falsch — nur eine erledigt)
- Badge "x3" koennte als "Prioritaet 3" missverstanden werden → klare Kennzeichnung noetig
- Aufgabe springt ploetzlich nach oben ohne erklaerbaren Grund

## Ist-Zustand (technisch)

### Recurring-Modell
- `recurrenceGroupID: String?` — verbindet alle Instanzen einer Serie
- `isTemplate: Bool` — Mutter-Instanz, unsichtbar im Backlog
- Neue Instanzen via `RecurrenceService.createNextInstance()` (beim Abschliessen) und `repairOrphanedRecurringSeries()` (App-Start)

### Priority Score (`TaskPriorityScoringService`)
- Formel: `min(100, eisenhower + deadline + neglect + completeness + nextUpBonus + blockerBonus)`
- **Kein Faktor fuer aufgelaufene Instanzen** — nur `rescheduleCount` als Neglect-Signal

### Backlog-Anzeige
- Jede Instanz erscheint als eigenständige Zeile — keine Gruppierung
- "Wiederkehrend"-View zeigt nur Templates, nicht Anzahl offener Kinder

## Feature-Skizze

### Teil 1 — Visuelles Stacking

Im Backlog: Instanzen mit gleicher `recurrenceGroupID` zu einer Zeile zusammenfassen.

- Badge "x3" anzeigen (Anzahl offener Instanzen der Serie)
- Visuelle Eskalation: x1 normal, x2 leicht hervorgehoben, x3+ deutlich
- Optional: "Seit 3 Wochen offen" als Zusatzinfo (aeltestes `dueDate` der Serie)
- Beim Abhaken: Aelteste Instanz (fruehestes `dueDate`) erledigen, Zaehler sinkt

### Teil 2 — Priority Boost

Neuer Faktor in `TaskPriorityScoringService`: `stackingBoost`

- z.B. +5 pro zusaetzlicher offener Instanz (max +15 bei 4+)
- Aufgelaufene Serien rutschen automatisch nach oben
- Boost gilt fuer die sichtbare (gruppierte) Zeile
