## Implementation Details

### 1. SyncEngine.swift — Neue Methoden (+25 LoC)

Zwei neue public Methoden nach dem bestehenden Pattern (findTask → modify → save):

```swift
func scheduleTask(itemID: String, date: Date, duration: Int?) throws {
    guard let task = try findTask(byID: itemID) else { return }
    // Mutual Exclusion: Clear FocusBlock assignment
    task.assignedFocusBlockID = nil
    // Set scheduling
    task.scheduledDate = date
    task.scheduledDuration = duration
    task.modifiedAt = Date()
    try modelContext.save()
}

func unscheduleTask(itemID: String) throws {
    guard let task = try findTask(byID: itemID) else { return }
    task.scheduledDate = nil
    task.scheduledDuration = nil
    task.modifiedAt = Date()
    try modelContext.save()
}
```

Aenderungen in bestehenden Methoden:

- **`completeTask()` (Zeile ~173):** Nach `task.assignedFocusBlockID = nil` einfuegen:
  ```swift
  task.scheduledDate = nil
  task.scheduledDuration = nil
  ```

- **`updateAssignedFocusBlock()` (Zeile ~247):** Nach `task.assignedFocusBlockID = focusBlockID` einfuegen:
  ```swift
  if focusBlockID != nil {
      task.scheduledDate = nil
      task.scheduledDuration = nil
  }
  ```

### 2. PlanningView.swift — Drop-Handler + loadData (+35 LoC)

**loadData():**
- Bestehender Code laesst `unscheduledTasks` alle incomplete Tasks enthalten
- Neu: Filter auf `!item.isScheduled` fuer MiniBacklogView
- Neu: Scheduled Tasks fuer `selectedDate` werden separat als `[TimelineItem]` geladen und an TimelineView uebergeben

**scheduleTask() — ersetzt EventKit-Call:**
- VORHER: `eventKitRepo.createCalendarEvent(title:startDate:endDate:reminderID:)` → erstellt echten Kalender-Event
- NACHHER: `try syncEngine.scheduleTask(itemID: transfer.id, date: startTime, duration: transfer.duration)` → rein SwiftData

**unscheduleTask(_:) — umbenennen von unscheduleEvent():**
- VORHER: Loescht CalendarEvent + markiert Reminder als incomplete (EventKit)
- NACHHER: `try syncEngine.unscheduleTask(itemID:)` — raeumt scheduledDate via SwiftData
- Methode umbenennen von `unscheduleEvent(_:)` zu `unscheduleTask(_:)` (Parameter: PlanItem ID)

**confirmationDialog:**
- VORHER: `if event.reminderID != nil` → Unschedule Button
- NACHHER: Zwei Faelle unterscheiden — externer CalendarEvent vs. scheduled LocalTask
  - Scheduled LocalTask: Tap-Handler ruft `unscheduleTask(_:)` auf
  - CalendarEvent: bestehender Flow bleibt unveraendert

### 3. TimelineView.swift — Neuer Parameter (+10 LoC)

- Neuer Parameter: `scheduledTasks: [TimelineItem] = []`
- Im Body: Scheduled Tasks als einfache Kapsel-Overlays rendern (gleiche Position-Logik wie Events)
- Phase C ersetzt diese Kapsel durch den `ScheduledTaskBlock` mit eigenem Design
- `onScheduleTask` Callback und alle bestehenden Parameter bleiben unveraendert

### 4. MiniBacklogView.swift — Kein Change

Filter passiert in `PlanningView.loadData()`. MiniBacklogView bekommt bereits das vorgefilterte Array — keine Aenderung an MiniBacklogView noetig.

## Mutual Exclusion Rule

Ein Task kann ENTWEDER `scheduledDate` ODER `assignedFocusBlockID` haben, niemals beides.

Enforcement an allen Write-Sites:

| Write-Site | Aktion |
|-----------|--------|
| `scheduleTask()` | Raeumt `assignedFocusBlockID` |
| `updateAssignedFocusBlock()` (focusBlockID != nil) | Raeumt `scheduledDate` + `scheduledDuration` |
| `completeTask()` | Raeumt beides |

## CloudKit / Sync

SwiftData + CloudKit sync funktioniert automatisch:
- `scheduledDate` und `scheduledDuration` sind Optional-Properties mit nil-Default — keine manuelle CKRecord-Mapping noetig
- `modifiedAt = Date()` wird bei jeder Aenderung gesetzt — CloudKit Last-Writer-Wins Conflict Resolution funktioniert korrekt
- Wenn auf iOS ein Task scheduled wird: CloudKit synced `scheduledDate` automatisch nach macOS
- macOS kann den Task in seiner eigenen PlanningView anzeigen (Phase D)
- EventKit CalendarEvents werden fuer Task-Scheduling NICHT mehr erstellt — kein EventKit-Sync-Concern

## Expected Behavior

- **Input:** PlanItemTransfer (Drag&Drop Payload) mit Task-ID + Ziel-Zeitslot auf Timeline
- **Output:** Task bekommt `scheduledDate` gesetzt, verschwindet aus MiniBacklog, erscheint auf Timeline
- **Unschedule:** Tap auf scheduled Task → Confirmation → `scheduledDate = nil` → Task kehrt in MiniBacklog zurueck
- **Side effects:**
  - SwiftData save() nach jeder Schedule/Unschedule-Aktion
  - CloudKit sync der geaenderten Task-Properties (automatisch)
  - Kein EventKit-Call, keine Calendar-Permission noetig fuer Task-Scheduling

## Known Limitations

- Scheduled Tasks haben in Phase B noch kein eigenes visuelles Design auf der Timeline — einfache Kapsel als Platzhalter (Phase C: ScheduledTaskBlock)
- Notification Reconciliation bei Schedule-Aenderung kommt in Phase D
- macOS PlanningView wird in Phase D angepasst — Logik wird bereits via CloudKit automatisch synced
- GapFinder beruecksichtigt scheduled Tasks noch nicht (Phase D)
- Keine Validierung von negativen scheduledDuration-Werten — Write-Sites pruefen nur auf nil
