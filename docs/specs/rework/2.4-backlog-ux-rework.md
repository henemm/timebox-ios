# Story 2.4: Backlog UX Rework

**Epic:** 2 — Adaptive Tagesplanung
**Priorität:** Niedrig | **Abhängigkeiten:** Story 1.3

## Ziel

Backlog-Ansicht mit Parkdeck-Metapher: Aktive Tasks prominent, selten relevante Tasks visuell zurückgestuft.

## Akzeptanzkriterien

- [x] Default-Ansicht zeigt nur `doNow` und `planSoon` ("Aktive Tasks")
- [x] `eventually`/`someday` hinter ausklappbarem "Parkdeck"-Bereich (collapsed by default)
- [x] Parkdeck zeigt Badge mit Anzahl, nicht die Tasks selbst
- [x] Swipe/Drag zum Parken oder Aktivieren
- [x] Suchfunktion durchsucht immer ALLE Tasks
- [x] Bestehende 5 View-Modi bleiben als Filter verfügbar

## Technische Vorgaben

### Betroffene Dateien
| Datei | Änderung |
|---|---|
| `BacklogView.swift` | Aktiv-Sektion + Parkdeck-Sektion |
| `BacklogRow.swift` | + Swipe-Action "Parken" / "Aktivieren" |
| `MacBacklogRow.swift` | + Context Menu Einträge |

### Constraints
- Parkdeck-Bereich: Lazy Loading (nicht rendern wenn collapsed)
- Keine Änderung an `TaskPriorityScoringService` Scoring-Logik

## Plattform

- **macOS:** Eigene View
- **Logik shared:** Parkdeck-Filterlogik in `Sources/` (welche Tasks aktiv vs. geparkt)
- **macOS-spezifisch:**
  - `MacBacklogRow.swift`: Context Menu Eintraege "Parken" / "Aktivieren" (statt Swipe)
  - Parkdeck-Sektion in macOS Backlog: Collapsible Section in Sidebar oder Content-Area
  - Badge-Count fuer geparkte Tasks in Sidebar sichtbar
- **Abweichung:** iOS = Swipe Actions, macOS = Context Menu (bestehendes Pattern)
