# RW_3.5 — Recurring Stacking: Visuelle Gruppierung + Priority Boost

## Approval

- [ ] Approved

## Purpose

When a user misses a recurring task multiple times, multiple open instances accumulate with the same `recurrenceGroupID`. This feature groups them visually into a single row with a count badge (e.g. "x3"), boosts their priority score based on stack depth, and completes only the oldest instance when the user taps the checkbox — so the badge decrements rather than everything disappearing.

## Implementation Details

### 1. Scoring — `TaskPriorityScoringService`

New factor added to the existing formula:

```
stackingBoost = min(15, 5 * max(0, stackedInstanceCount - 1))

Updated formula:
min(100, eisenhower[0-50] + deadline[0-25] + neglect[0-15]
        + completeness[0-5] + nextUp[0-5] + blocker[0-9]
        + stackingBoost[0-15])
```

- Stack depth 1 → boost = 0 (no change)
- Stack depth 2 → boost = +5
- Stack depth 3 → boost = +10
- Stack depth 4+ → boost = +15 (capped)

### 2. Model — `PlanItem`

Add one stored property that grouping logic sets from outside:

```swift
var stackedInstanceCount: Int = 1
```

This is NOT persisted — it is computed fresh every time the Backlog list is built.

### 3. Grouping Logic — `BacklogView`

After fetching `planItems` from `syncEngine.sync()`, before rendering:

```
1. Separate items with a recurrenceGroupID from ungrouped items.
2. For each distinct recurrenceGroupID with count >= 2:
   a. Sort group by dueDate ASC.
   b. Designate the item with the oldest dueDate as the representative.
   c. Set representative.stackedInstanceCount = group.count.
   d. Drop non-representative items from the display list.
3. Re-sort merged list by priority score (representative uses boosted score).
4. Apply the same grouping to ALL view modes: Priority, Recent, Overdue.
5. Within the Parkdeck section: group only active-status instances; parked
   instances that share a recurrenceGroupID with active ones are treated
   separately (each section is grouped independently).
```

### 4. Completion Flow — `BacklogView`

When user taps the checkbox on a stacked row:

```
1. Look up all open planItems sharing the same recurrenceGroupID.
2. Sort by dueDate ASC.
3. Call completeTask(oldestInstance.id) via SyncEngine.
4. RecurrenceService.createNextInstance() fires as normal.
5. Grouping logic runs on next render:
   - Badge decrements (x3 → x2).
   - When count reaches 1: badge disappears, normal row display.
```

DeferredCompletionController handles the animation — no changes needed there.

### 5. Badge UI — `BacklogRow`

New parameter: `stackedCount: Int` (default `1`).

```
stackedCount == 1  → No badge rendered
stackedCount == 2  → Badge "x2", foreground color .secondary
stackedCount >= 3  → Badge "x{n}", foreground color .orange,
                     row background gets subtle warm tint
```

Accessibility identifier pattern: `stackingBadge_<taskId>`

Uses existing `BacklogRow` identifier patterns for the row itself.

## Expected Behavior

- **Input:** Multiple open `PlanItem` instances sharing the same `recurrenceGroupID`
- **Output:** Single row in Backlog with stacking badge; boosted sort position
- **Side effects:**
  - Tapping checkbox completes only the oldest instance (not all)
  - Score boost is ephemeral — recomputed each render, not stored
  - All view modes (Priority, Recent, Overdue) show the grouped row

## Known Limitations

- No expand/collapse of stacked groups — future enhancement
- macOS parity deferred to Phase B
- DayView and MorningCoaching show individual suggestions — no stacking there
- Tasks sharing the same title but with different (or nil) `recurrenceGroupID` do not stack — this is correct behavior
- Search/filter matches on title: stacked group appears if any instance title matches

## Edge Cases

| Case | Behavior |
|------|----------|
| Some instances parked, some active | Group within each section independently; a parked x2 group and an active x1 can coexist |
| Next Up flag on a stacked series | Oldest instance carries the Next Up flag; stacking boost still applies |
| Single instance | `stackedInstanceCount = 1`, no badge, no boost — normal display |
| All instances in Overdue section | Stacked group appears once in overdue |
| Delete series | Existing "Delete all" dialog operates on `recurrenceGroupID` — unchanged |
