# BehavioralProfileService Phase B — Kalender-Korrelation & Verschiebungs-Muster

## Approval

- [ ] Approved

## Purpose

Erweiterung des bestehenden BehavioralProfileService um zwei fehlende Komponenten aus Story 0.2:
1. **Kalender-Korrelation:** Wie beeinflusst die Meeting-Dichte die Task-Produktivitaet?
2. **Verschiebungs-Muster:** Welche Tasks werden chronisch verschoben und was haben sie gemeinsam?

Diese Daten werden spaeter von NextUpSuggestionService, LimitationGuard und EmotionalNudgeService konsumiert.

## Implementation Details

### Komponente 4: Kalender-Korrelation

#### Neue Types

```swift
/// Meeting-Dichte eines Tages.
/// Nur non-allDay CalendarEvents zaehlen als "Meeting".
enum MeetingLoad: String, CaseIterable, Hashable {
    case low    // 0-2 Meetings/Tag
    case medium // 3-4 Meetings/Tag
    case high   // 5+ Meetings/Tag
}
```

#### Neues Feld auf BehavioralProfile

```swift
/// Durchschnittliche Task-Completion pro Meeting-Dichte.
/// Key = MeetingLoad, Value = durchschnittliche erledigte Tasks/Tag.
/// Nur Buckets mit >= 3 Tagen werden aufgenommen; fehlende Buckets = nicht genug Daten.
/// nil = insgesamt weniger als 5 Tage mit sowohl Tasks als auch Kalender-Daten.
let capacityByMeetingLoad: [MeetingLoad: Double]?
```

#### Berechnung

```
computeCapacityByMeetingLoad(from completedTasks: [LocalTask], calendarEvents: [CalendarEvent]) -> [MeetingLoad: Double]?

1. Fuer jeden Tag im 28-Tage-Fenster:
   a. Zaehle non-allDay CalendarEvents → meetingCount
   b. Klassifiziere: 0-2 = .low, 3-4 = .medium, 5+ = .high
   c. Zaehle completed Tasks dieses Tages
2. Pro MeetingLoad-Bucket:
   - Nur Buckets mit >= 3 Tagen aufnehmen
   - avg = totalTasks / totalDays
3. Gesamtschwelle: Mindestens 5 Tage mit sowohl Tasks als auch Events, sonst nil
```

#### Signatur-Aenderung

`compute()` und `profile()` bekommen neuen Parameter: `calendarEvents: [CalendarEvent] = []`

Default `[]` stellt sicher, dass bestehende Call-Sites (Tests!) nicht brechen.

#### Schwelle

```swift
static let minDaysForMeetingLoad: Int = 3  // pro Bucket
static let minTotalDaysForCalendarCorrelation: Int = 5  // gesamt
```

### Komponente 5: Verschiebungs-Muster

#### Neue Types

```swift
/// Ein Cluster von chronisch verschobenen Tasks mit gemeinsamen Merkmalen.
struct ProcrastinationPattern: Equatable {
    /// Die gemeinsame Kategorie dieses Clusters (nil = unkategorisiert oder gemischt).
    let category: TaskCategory?
    /// Anzahl Tasks in diesem Cluster.
    let taskCount: Int
    /// Durchschnittlicher rescheduleCount der Tasks im Cluster.
    let avgRescheduleCount: Double
    /// Durchschnittliche Importance der Tasks im Cluster (nil = keine importance gesetzt).
    let avgImportance: Double?
}
```

#### Neues Feld auf BehavioralProfile

```swift
/// Verschiebungs-Muster: Cluster von Tasks mit rescheduleCount >= 3.
/// Sortiert nach taskCount absteigend.
/// nil = weniger als 3 Tasks mit rescheduleCount >= 3.
let procrastinationPatterns: [ProcrastinationPattern]?
```

#### Berechnung

```
computeProcrastinationPatterns(from allTasks: [LocalTask]) -> [ProcrastinationPattern]?

WICHTIG: Kein 28-Tage-Fenster! Alle Tasks (completed + nicht-completed) mit rescheduleCount >= 3.

1. Filter: allTasks.filter { $0.rescheduleCount >= 3 }
2. Schwelle: < 3 Tasks → nil
3. Gruppierung nach TaskCategory:
   - TaskCategory(rawValue: task.taskType) → Kategorie oder nil
   - Pro Kategorie (inkl. nil = "unkategorisiert"):
     - taskCount = Anzahl Tasks
     - avgRescheduleCount = Durchschnitt rescheduleCount
     - avgImportance = Durchschnitt importance (nur von Tasks mit importance != nil; nil wenn keine)
4. Sortierung: nach taskCount absteigend
```

#### Schwelle

```swift
static let minTasksForProcrastination: Int = 3
```

## Expected Behavior

- **Input:** Arrays von LocalTask, FocusBlock, CalendarEvent + now: Date
- **Output:** BehavioralProfile mit allen 5 Komponenten (3 bestehend + 2 neu)
- **Side effects:** Keine (reiner Rechenservice, in-memory Cache)

## Known Limitations

- CalendarEvents muessen vom Aufrufer bereitgestellt werden (kein eigener EventKit-Zugriff)
- `rescheduleCount` wird nur bei Tasks mit dueDate inkrementiert — Tasks ohne dueDate tauchen nie in ProcrastinationPatterns auf
- MeetingLoad-Buckets koennen im Dict fehlen wenn nicht genug Tage vorhanden
