# RW_4.2 — Success Story Generator

## Purpose

KI-generierte Tages-Zusammenfassung (2-4 Sätze) im Evening Mode des DayView, basierend auf erledigten Tasks, Focus-Zeit und überwundenen Blockaden. Pro Tag einmal generiert und gecacht — mit Fallback auf statische Templates ohne Apple Intelligence.

## Implementation Details

### 1. AppSettings.swift — Cache-Felder

```swift
@AppStorage("cachedSuccessStory") var cachedSuccessStory: String = ""
@AppStorage("cachedSuccessStoryDate") var cachedSuccessStoryDate: String = ""
```

Cache-Key ist ISO-8601-Datum (yyyy-MM-dd). Gleiche Date → Story aus Cache servieren, kein neuer Foundation-Model-Aufruf.

---

### 2. SuccessStoryService.swift — Struktur

```swift
enum SuccessStoryService {

    static var isAvailable: Bool {
        #if canImport(FoundationModels)
        if #available(iOS 26.0, macOS 26.0, *) {
            return SystemLanguageModel.default.availability == .available
        }
        #endif
        return false
    }

    static func generate(
        completedTasks: [PlanItem],
        focusBlocks: [FocusBlock],
        settings: AppSettings
    ) async -> String {
        let today = isoDate(Date())

        // Cache-Hit: selber Tag, Story bereits vorhanden
        if settings.cachedSuccessStoryDate == today,
           !settings.cachedSuccessStory.isEmpty {
            return settings.cachedSuccessStory
        }

        let story: String
        if isAvailable && !completedTasks.isEmpty {
            story = (try? await generateWithAI(completedTasks: completedTasks, focusBlocks: focusBlocks))
                    ?? fallback(completedTasks: completedTasks, focusBlocks: focusBlocks)
        } else {
            story = fallback(completedTasks: completedTasks, focusBlocks: focusBlocks)
        }

        settings.cachedSuccessStory = story
        settings.cachedSuccessStoryDate = today
        return story
    }

    // Private
    private static func generateWithAI(...) async throws -> String { ... }
    private static func fallback(completedTasks: [PlanItem], focusBlocks: [FocusBlock]) -> String { ... }
    private static func isoDate(_ date: Date) -> String { ... }
}
```

### 3. Prompt-Strategie

System-Prompt:
```
Du bist ein motivierender persönlicher Assistent.
Fasse den Tag des Nutzers positiv zusammen. Schreibe 2-4 Sätze.
Motivierend, aber authentisch. Keine leeren Floskeln.
Antworte ausschließlich mit dem fertigen Text, ohne Einleitung oder Erklärung.
```

User-Prompt (dynamisch zusammengebaut):
```
Erledigte Tasks: [Titel + Kategorie, max 10, kommasepariert]
Focus-Zeit: [X Minuten gesamt aus focusBlocks.duration]
Überwundene Blockaden: [Tasks mit rescheduleCount > 0 die heute erledigt wurden — nur Titel]
```

Foundation Models Aufruf:
```swift
#if canImport(FoundationModels)
if #available(iOS 26.0, macOS 26.0, *) {
    let session = LanguageModelSession {
        "System-Prompt..."
    }
    let response = try await session.respond(to: userPrompt)
    return response.content  // plain String, kein @Generable nötig
}
#endif
```

### 4. Fallback-Templates

**0 erledigte Tasks:**
```
Heute war ein ruhiger Tag – manchmal braucht es das auch.
Morgen ist ein neuer Anfang mit frischer Energie.
```

**>0 Tasks, kein Apple Intelligence:**
```
Du hast heute [N] Task(s) erledigt[, darunter: Titel1, Titel2].
[Wenn focusMinutes > 0: Du hast [X] Minuten fokussiert gearbeitet. ]Gut gemacht!
```

Platzhalter `[N]`, `[X]`, Titel werden zur Laufzeit eingesetzt — kein String-Template-Framework nötig.

### 5. SuccessStoryView.swift — Struktur

```swift
struct SuccessStoryView: View {
    let completedTasks: [PlanItem]
    let focusBlocks: [FocusBlock]
    @StateObject private var settings = AppSettings.shared  // oder @EnvironmentObject
    @State private var story: String? = nil
    @State private var isLoading = true

    var body: some View {
        Group {
            if isLoading {
                // Lade-Spinner (ProgressView)
            } else if let story {
                // Text-Card
            }
        }
        .task {
            story = await SuccessStoryService.generate(
                completedTasks: completedTasks,
                focusBlocks: focusBlocks,
                settings: settings
            )
            isLoading = false
        }
        .accessibilityIdentifier("successStoryCard")
    }
}
```

Kein gemeinsamer `@State` mit `loadEveningData()` — Foundation-Model-Aufruf läuft vollständig entkoppelt in der View selbst.

## Expected Behavior

- **Input:** `completedTasks: [PlanItem]`, `focusBlocks: [FocusBlock]` (bereits in loadEveningData() geladen), Datum des Tages
- **Output:** Card mit 2-4 Sätzen motivierendem Text, sichtbar im Evening Mode des DayView
- **Side effects:**
  - `AppSettings.cachedSuccessStory` und `AppSettings.cachedSuccessStoryDate` werden pro Tag einmalig beschrieben
  - Foundation-Model-Aufruf läuft asynchron — UI zeigt Lade-Spinner bis Antwort vorliegt
  - Bei Simulator/ohne Apple Intelligence: Fallback-Text erscheint sofort ohne Spinner-Verzögerung

**Caching-Verhalten:**
- Selber Tag + Story vorhanden → sofort aus Cache, kein Spinner, kein KI-Aufruf
- Neuer Tag oder leerer Cache → Spinner → KI-Aufruf (oder Fallback) → Story speichern

**Accessibility:**
- Card-Container: `accessibilityIdentifier("successStoryCard")`
- Loading-View: `accessibilityIdentifier("successStoryLoadingView")`

## Known Limitations

- Apple Intelligence ist nur auf Physical Devices mit A17 Pro oder M-Series verfügbar — im Simulator immer Fallback
- `LanguageModelSession` Qualität variiert nach Gerät und Systemlast — Antwortzeit nicht garantiert
- Kein Retry-Mechanismus bei Foundation-Model-Fehler — bei Fehler direkt Fallback (try? pattern)
- Cache wird nicht invalidiert wenn der Nutzer nachträglich Tasks als erledigt markiert — Story bleibt die des ersten Aufrufs an diesem Tag
- Kein @Generable / strukturierte Ausgabe — Modell gibt Freitext zurück, kein Schema-Enforcement
